使用 `correction_run_001/step_100000.pt` 的 EMA，原正式 50k 为父权重。50,001–100,000 的 50,000 条训练记录连续，loss、梯度及模型／EMA 权重全部有限；M4 父证据、纠偏数据、归一化、源码及训练工具版本绑定通过。

宿主训练硬件为 RTX 5080，当前会话 CUDA 不可用，后续检查为 CPU FP32。100k EMA validation loss 为 0.00925038。原 validation 的 105 个窗口、30 个回合、噪声种子 0/1/2，配对 trailing／leading 采样均有限，标签 mask 只用于统计。

## 新示范拟合与闭环泛化

重新计算原 teacher 在当前早期姿态上的角速度参考，与新增示范的真实 teacher 标签最大差为 6.04e-8 rad/s。仅用作离线诊断，未在物理执行中下发。

对全部 74 个纠偏训练窗口及 45 个实际失败条件（2–5 秒），用相同初始噪声比较 50k／100k EMA。仅在参考角速度至少 0.05 rad/s 的样本上统计幅度比，分别有 44／34 个窗口。幅度比定义为预测角动作在教师参考上的投影除以参考平方范数。

| 条件 | 50k 三种子投影比中位数 | 100k 三种子投影比中位数 |
| --- | --- | --- |
| 新增纠偏训练窗口 | 0.120／0.191／0.109 | 1.0003／1.0005／0.9931 |
| 实际闭环失败条件 | 0.0039／−0.0048／−0.0037 | 0.0212／0.0073／0.0111 |

新增示范的局部纠偏已被拟合，但真实失败条件上的纠偏很弱。最近纠偏示范与实际失败条件的 TCP 位置距离中位数 16.4 mm，90 分位为 74.2 mm；归一化条件 RMS 不是经过校准的 OOD 判据。

这支持上方安全点示范的泛化范围不足，不能证明它是唯一原因。仍应检查路径位置／进度、剩余姿态误差及低角速度的联合覆盖；不能只重复训练现有四条示范，或因 loss 下降追加预算。

## 宿主 CUDA 三场复核

先保持权重与设置不变，在宿主 GPU 复核同三场；新输出目录必须不存在：

```bash
cd /home/minashiki/FeedingRobot_DPRL
/home/minashiki/anaconda3/envs/feedingrobot/bin/python tools/m5/eval_correction.py pickup \
  --base-checkpoint outputs/single_bean/v1/m5/dit/run_001/step_50000.pt \
  --checkpoint outputs/single_bean/v1/m5/dit/correction_run_001/step_100000.pt \
  --data-report outputs/single_bean/v1/m5/dit/correction_dataset_v1_001/report.json \
  --device cuda \
  --output outputs/single_bean/v1/m5/dit/correction_pickup_100000_cuda_001
```

CUDA 的随机序列与 autocast 精度可能改变轨迹，因此 CPU 结果不等同于 CUDA 结果。若 CUDA 同样 pickup 0/3，下一步是针对实际偏离状态设计、校准少量纠偏示范，覆盖不同 ACQUIRE 路径位置／进度和较小残差，保持原物理保护、合法标签和完整成功规则；先验证 teacher 在这些状态上能安全完成。

只有拾豆改善后才扩大到正常／恢复各 15 场完整 validation。达标后再建设正式评估入口的新数据／推理修订审计，随后才运行 test 与考虑冻结。
